## 2. Architecture

```
Discord ─▶ Kimaki frontend (discord-bot, preprocessing, interactions, commands)
             └─ capability-aware backend boundary (default: OpenCode; ZCode opt-in, default-off)
                  ├─ OpenCodeBackend = existing ThreadSessionRuntime (unchanged behavior)
                  └─ ZCodeBackend   = adapted coordinator + zcode-backend (durable sidecar store)
                        └─ shared native core cli/src/agent/native/ (host-independent)
                              └─ owned app-server child process (NDJSON RPC)
```

- Native core (`cli/src/agent/native/`): types, errors, ndjson, client, protocol, model,
  diagnostics, process, supervisor. No Discord/Kimaki-SQL/OpenCode/Subrouter imports.
- Durable sidecar: ten `agent_*` tables through the real Drizzle schema + `drizzle-kit export`,
  with a version/integrity gate in `db.ts` **before** generic `CREATE TABLE IF NOT EXISTS` DDL.
- ZCode owns model/tools/context/loop; Kimaki only authorizes input, renders output,
  and owns durable admission (SEND_INTENT, CAS, outbox receipts, leases).

## 3. Invariants (from REVIEW_FINDINGS/mission; do not weaken)

1. Default stays OpenCode; every ZCode path is behind explicit opt-in; missing sidecar for
   a `zc:` ID throws — never falls back to OpenCode.
2. Backend resolved before any OpenCode init (constructor/ensure/preprocessing/SDK/global listener).
3. One admitted input → at most one native submission (durable SEND_INTENT); unknown delivery
   is never replayed; no fresh-session/first-model fallback; no synthetic "continue".
4. Native tools are display-only in Kimaki; zero OpenCode model/tool calls on native routes.
5. Cancellation keeps ownership until writers verifiably stop (or state stays unknown/locked).
6. Terminal status comes from authoritative native execution state, never V4 presentation rows.
7. Interactions use fresh opaque one-use IDs bound to one RPC/generation; answers reply to the
   original request; never converted to an ordinary session/send; no autoapprove; no LLM answers.
8. No `retryLastUserPrompt`/empty-prompt abort on ZCode model changes; readback semantics instead.
9. `/btw` = conversation-only V4 fork at validated epoch; no legacy filesystem-restoring fork;
   no guessed paging/CAS until capture-backed.
10. Secrets redacted at every boundary (encoded forms, tool names, diagnostics ring); no
    credentials in fixtures/logs/Discord.
11. Old IDs/rows/semantics preserved; `thread_sessions.session_id` stays non-unique; additive only.
12. Native core stays host-independent (reusable later by Subrouter); keep it repository-local.
13. Windows native process ownership stays disabled until actually implemented and tested.
